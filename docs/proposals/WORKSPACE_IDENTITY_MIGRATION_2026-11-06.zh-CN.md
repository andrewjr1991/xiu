# POSIX 运行记录身份迁移方案（2026-11-06）

状态：只读预览已实现，实际归属与事务迁移仍是设计，不是已完成的运行记录迁移。

## 已确认的问题与本轮边界

旧 `TaskRunJournal` 身份把解析后的路径统一转成小写，并把反斜杠当分隔符；在 Linux 上，`Project` / `project` 和字面 `part\name` / 嵌套 `part/name` 是不同目录，却可落到同一个用户目录运行记录槽。隔离夹具实际创建两组目录，在第一目录完成一条假任务，第二目录读取到该条记录，两组均确认命名空间碰撞和外来记录可见。实验没有模型、外部写入或真实用户记录。

本轮桌面选择 ID 已按平台区分：Windows 保留原来的大小写/分隔符归一化，POSIX 保留真实路径的大小写与字面反斜杠。最近项目含已保存的规范路径，可在内存中重算选择 ID；读取不改写文件，显式重新打开时保存新 ID，不造成重复行。

**这不等于修复旧运行记录的命名空间。** 不能直接改 `TaskRunJournal` 的摘要算法：那会让旧中断记录、锁或未知副作用失去可见性。安全审计也有类似旧大小写归一化，后续须一并界定，不能把旧记录自动归给某个项目。

## 先完成只读预览

已增加 `xiu recover identity [json]`，报告当前旧身份、建议的版本化身份、旧槽/目标槽的文件元数据数量与字节、不可检查项和锁对象是否存在。只读元数据，不打开任务正文，不认定所有权或进程是否存活；目录缺失正常，链接/非普通对象排除且报告不完整。需要工作区信任，不发模型请求、不更改运行记录、锁、审批或恢复状态。

明确给出“所有权未核实、不可据此迁移或重放”，避免把空间统计变成安全证明。Windows 的现有身份保持；POSIX 新身份必须带版本区分，使所有旧记录均经过归属检查，不能只给含大写字符的目录换名字。

## 真正迁移的准入条件

1. 绑定准确的规范工作区、旧/新身份与预览版本；列明待归属的运行 ID、状态和未知操作计数，要求用户核实归属。旧摘要本身不能证明归属，不能因当前工作区已信任或模型文字而自动采用。
2. 工作区与两侧记录没有活跃任务；读取失败、未知格式、锁归属不明、上下文变化均拒绝。尚未核实的旧记录必须阻止新副作用，不能用“新目录为空”放行。
3. 显式用户确认，非 TTY、`--yes`、环境变量和历史不自动确认。保留当前恢复确认与未知副作用禁止重放规则，迁移不是恢复授权。
4. 私有备份与迁移账本先行，记录源/目标的内容摘要与文件身份；暂存、复核、原子提交。任一步失败保留旧记录与证据；结果未知时不重复写入，不静默删除旧槽。
5. 新旧记录的 ID、状态、时间和操作事实保持；完成归属后仅重绑定存储身份，不制造检查通过或任务完成。回退必须确认新槽尚无新操作并有完整证据，不能覆盖后续运行。

## 验收矩阵

- Linux 大小写目录与字面反斜杠目录隔离；macOS 按实际文件系统能力验证；Windows 现有大小写语义和升级兼容保留。
- 旧槽有完成/暂停/中断/未知副作用/损坏记录、旧槽/目标槽都有数据、活锁/PID 复用、链接/FIFO、读取权限错误。
- 预览后源/目标/工作区变化、用户取消、非 TTY、任意提交点中断；所有未完成迁移继续阻止副作用，零自动重放。
- 历史、CLI/桌面运行列表、恢复状态、审计与锁检查统一身份规则；不能只修一个入口。

真实迁移尚未实施。在完成前，不应把此候选描述为已修复 POSIX 运行记录隔离；避免让仅大小写不同或分隔符归一化后相同的项目共用旧运行记录槽，保留原记录并人工核实，不通过删除记录绕过恢复检查。
